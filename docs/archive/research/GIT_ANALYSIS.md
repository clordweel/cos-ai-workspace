# Git 分析内容与多次提交处理

> 说明如何在本项目中分析 Git 仓库内容，并**安全、可控地处理多次提交**（用于 changelog、代码审查上下文、Dify 知识库等）。

---

## 1. 分析内容范围

可分析的 Git 内容通常包括：

| 内容类型 | 说明 | 典型用途 |
|----------|------|----------|
| **提交信息** | `git log --oneline`、`--format` 等 | 变更摘要、changelog |
| **单次提交详情** | `git show <commit>`：作者、日期、diff | 单次变更上下文 |
| **多次提交批量** | 最近 N 条或某分支/时间范围 | 给 AI 的上下文、发布说明 |
| **文件变更列表** | `git diff --name-only A..B` | 影响范围统计 |
| **差异内容** | `git diff A..B` 或 per-commit diff | 代码审查、摘要生成 |

---

## 2. 多次提交的处理策略

### 2.1 按数量限制（推荐）

- 使用 `git log -n <N>` 限制条数，避免一次拉取过多。
- 建议默认 **N ≤ 50**；若需更多，可分页（`--skip`）或按时间范围再取。

### 2.2 按时间/分支范围

- 时间：`git log --since="2025-01-01" --until="2025-02-01"`
- 分支/区间：`git log main..feature --oneline`

### 2.3 输出格式

便于程序解析的格式示例：

```bash
# 单行 + hash + 标题
git log -n 20 --format="%h %s"

# 详细：hash / 作者 / 日期 / 标题 / body
git log -n 20 --format="%H%n%an%n%ad%n%s%n%b---COMMIT---"
```

解析时以 `---COMMIT---` 或换行规则拆分多次提交。

### 2.4 安全与权限

- **仅读操作**：只使用 `log`、`show`、`diff`、`status`，禁止 `checkout`、`reset`、`push` 等写操作。
- **仓库路径**：由配置或环境变量指定，不信任前端传入的任意路径，防止目录穿越。
- **执行环境**：若在中间层执行 git 命令，应在固定工作目录（如项目根）下执行。

---

## 3. 在本项目中的使用方式

### 3.1 与 Dify 的配合

- 将「最近 N 条提交」或「某次提交的 diff」作为上下文传入 Dify 对话或知识库，用于：
  - 生成发布说明、changelog；
  - 回答“最近改了什么”“某次提交改了哪些文件”等问题。
- 工具调用时建议限制单次请求的 commit 数量（如 20），避免 token 超限。

### 3.2 与 cos / ERP 无直接关系

Git 分析仅用于工作台内的协作与追溯，不写入 ERPNext；若需把「发布版本」「变更清单」记入 ERP，应通过 cos 或其它业务接口单独设计。

---

## 4. 实现要点小结

1. **多次提交**：用 `git log -n N` 或 `--since`/`--until` 控制范围和数量。
2. **内容分析**：用 `--format` 统一格式，便于解析；需要 diff 时用 `git show <hash>` 或 `git diff A..B`。
3. **安全**：只读、固定仓库路径、不执行写操作。
4. **性能**：限制单次返回条数，大范围分析时分页或按时间/分支切分。

以上约定可在需要时用命令行或脚本实现，或由外部工具/MCP 提供 Git 只读能力。
